# LK广播与CAN驱动主机回归

依赖Python 3及原生C++17编译器；默认调用PATH内的g++，可用环境变量CXX指定其他兼容编译器。

从仓库根目录运行：

```sh
python tests/host/test_lk_broadcast.py --output build/host/lk
python tests/host/test_can_driver.py --output build/host/can
```

成功标志：各程序退出码为0，results.log记录全部检查通过。build.log保留编译诊断。

测试抽取仓库实际实现，仅替换HAL/RTOS、时钟和基础类型。LK测试覆盖反馈有效期、首帧及跨零、多圈失效、接收时间、参与清单及官方广播字节示例；CAN测试覆盖立即到达的RX、队列分配失败重试、初始化错误传播、接收元数据和发送邮箱输出参数。

这些结果不能代替STM32完整构建，也不证明电机型号支持全部广播命令、四电机时序、实际停机、故障保护或机械安全。CAN结构新增字段后需完整重新编译；队列消费按sourceBus分流。

一控四专项还覆盖四种帧类型的全部24种对象排列、四个不同目标、交错A1回复的ID隔离、单节点故障隔离、各节点独立掉线及非连续ID1/ID3槽位。都是主机协议检查，不是四台电机实测。

型号与边界回归覆盖MF/MG默认兼容、MS的±850限幅及A0/9C功率原始反馈、混合型号槽位、非法型号拒绝、速度/位置完整int16边界、NaN/Inf、三种编码器位数与0x180反馈基址。当前LK检查227项，CAN检查15项；数量包括参数化排列，不能视为227种独立功能。
